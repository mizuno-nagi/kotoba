# NHK English Digest 项目计划书

## 1. 项目目标

在项目根目录 `nhk_english_digest` 下实现一个每日自动抓取、AI 注释和本地展示的英语学习工具：

- 每日抓取 NHK WORLD-JAPAN 英语新闻
- 使用 OpenAI 兼容 API（默认 DeepSeek）生成中文注释
- 每篇新闻生成四级翻译、六级翻译、重点词汇、难句解析、背景补充
- 所有内容保存为本地 Markdown 文件
- 通过 Flask 本地 Web 界面浏览，并支持在页面保存 API Key
- 通过 schedule 实现每日定时任务

## 2. 技术方案

| 模块 | 技术 | 说明 |
| --- | --- | --- |
| 网络抓取 | requests + BeautifulSoup + lxml | 优先 RSS，失败降级为离线示例 |
| AI 注释 | OpenAI 兼容 Chat Completions API | 默认 DeepSeek，temperature=0.2 |
| 数据存储 | 本地 Markdown | `output/YYYY-MM-DD/` 按日期归档 |
| Web 界面 | Flask + Jinja2 | 本地端口 5000，响应式，离线可用 |
| 定时任务 | schedule | 默认每天 07:00 执行 |
| 配置 | YAML | `config.yaml` 管理 API Key、模型、抓取参数 |

## 3. 文件结构

```text
nhk_english_digest/
├── config.yaml          # API 与抓取配置
├── scraper.py           # NHK 新闻抓取 + 离线降级数据
├── annotator.py         # AI 注释，含 JSON 解析、重试、模拟输出
├── main.py              # 主流程：抓取 -> 注释 -> 写 Markdown
├── web_app.py           # Flask Web 服务
├── scheduler.py         # 每日定时任务
├── requirements.txt     # Python 依赖
├── README.md            # 安装与运行说明
├── 计划书.md             # 本计划文档
├── templates/           # Jinja2 模板
└── output/              # 每日输出目录（生成后出现）
```

## 4. 实施步骤

### 阶段一：项目骨架与配置

- 创建项目目录与 `.gitignore`
- 编写 `config.yaml`，包含 `openai_base_url`、`openai_api_key`、`model`、`max_articles`、`request_timeout`、`schedule_time`

状态：已完成。

### 阶段二：抓取模块

- 实现 `Scraper` 类
- 优先解析 `https://www3.nhk.or.jp/rss/news/cat0.xml`
- 对每篇文章抓取 HTML 并提取正文
- 内置两篇约 200-300 词的离线示例新闻，网络失败时降级
- 统一使用 `requests.Session` 和 User-Agent

状态：已完成。

### 阶段三：AI 注释模块

- 实现 `Annotator` 类
- 按目标文件要求写入固定 system prompt
- 调用 OpenAI 兼容 `/chat/completions`
- 设置 `temperature=0.2`、`max_tokens=4000`
- 解析 JSON，失败重试一次，仍失败返回默认错误结构
- 未配置 API Key 时使用可展示完整流程的模拟注释

状态：已完成。

### 阶段四：主流程与 Markdown 输出

- 实现 `main.py`
- 加载 `config.yaml`
- 实例化 `Scraper` 并抓取当天新闻
- 实例化 `Annotator` 逐篇注释
- 写入 `output/YYYY-MM-DD/序号_英文标题.md`
- 同时生成 `index.md`，包含标题、摘要与链接
- 当天输出目录已存在且非空时跳过，避免重复消耗 API

状态：已完成。

### 阶段五：Web 界面

- 实现 `web_app.py`
- 路由：
  - `/`：按日期倒序列出日报卡片
  - `/daily/<date>`：当天新闻列表
  - `/article/<date>/<filename>`：单篇 Markdown 详情页
  - `/settings`：保存 DeepSeek API Key
- Jinja2 模板放在 `templates/`
- CSS 内嵌在模板中，不使用外部 CDN
- 浅色主题 `#4A90D9` / `#F5F7FA`
- 毛玻璃卡片、词汇表格、难句 blockquote、响应式布局

状态：已完成。

### 阶段六：定时任务

- 实现 `scheduler.py`
- 使用 `schedule` 按 `config.yaml` 的时间执行 `main.py` 主逻辑
- 支持 Ctrl+C 停止

状态：已完成。

### 阶段七：依赖安装与本地验证

- 创建 Python 虚拟环境 `.venv`
- 安装 `requirements.txt` 中的依赖
- 运行 `python main.py` 验证：
  - 抓取成功使用离线示例数据
  - 未配置 API Key 时注释走模拟输出
  - `output/2026-08-15/` 生成独立新闻 Markdown 与 `index.md`
- 运行 `python web_app.py` 验证：
  - 服务监听 `127.0.0.1:5000`
  - 首页、日报列表、详情页、设置页均可访问

状态：待执行。

## 5. 验证方式

1. 检查项目文件完整且可导入
2. 执行 `python main.py`，确认日志输出和 Markdown 文件生成
3. 执行 `python web_app.py`，用本地 HTTP 请求确认页面返回 200
4. 检查 `output/2026-08-15/index.md` 与新闻详情页内容渲染正常

## 6. 风险与应对

| 风险 | 应对 |
| --- | --- |
| NHK 网络请求失败 | 自动降级为内置离线示例，保证流程可演示 |
| 未配置 API Key | 使用模拟注释输出完整 JSON 结构 |
| API 返回非 JSON | 重试一次，仍失败返回默认错误结构 |
| Python 3.14 依赖兼容问题 | 使用内置 Python 3.12 创建虚拟环境 |
| 5000 端口被占用 | 检测占用情况；必要时改用可用端口并说明 |
